# llm-bench — project instructions

This directory is a PUBLIC GitHub repository (BobBoba/llm-bench). Everything committed here is visible to the world.

## Hard rules for anything committed

- No secrets, keys, tokens, internal hostnames, or private IPs. Keys come from env vars or key files (`/tmp/.orkey`, `LLAMA_SERVER_KEY_FILE`) that are never committed.
- No proprietary trading-platform names anywhere in this repo (names, code, comments, commit messages). Use neutral wording if ever relevant.
- Never state that any content here was generated by or with an AI assistant. Commit messages are plain and factual: what was benchmarked, what changed.
- `results/hard-dumps/` (raw model answers) and `NOTES-ru.md` (internal notes) are gitignored — keep them that way.

## Workflow: benchmarking a new model

The full playbook lives in the `bench-model` skill (`~/.claude/skills/bench-model/`). Short version:

1. Probe the model with one cheap call first (routing/endpoint/auth confirmed before a campaign).
2. `node runners/run-hard.mjs --selftest` before every campaign — references must pass their own oracles.
3. Run the batteries with a fresh `OUT=results-….json`; runs are crash-safe and resumable.
4. Update the sheet via the `gsheets_*.py` scripts (they preserve manual formatting — never delete conditional-format rules blindly).
5. Commit results + any script changes: one commit per campaign, message names the model(s). Git history is the benchmarking journal.

## Invariants that keep results comparable

- One configuration per model row: window, KV type, quant, budget are fixed for all 22 units; if config changes mid-campaign, delete the affected records and re-measure.
- Failed *calls* (routing, timeout, server crash) are `ok:false` and excluded from denominators; failed *tasks* are `ok:true, solved:false`. Never mix them.
- Only one runner instance may write a given results file (whole-file rewrite on save). Kill by PID from `pgrep -a`, never `pkill -f` (the shell wrapper matches its own pattern and kills itself instead).
- Local models: config overrides apply at model LOAD time — after changing them, force a reload and verify the actual server flags before measuring speed.
