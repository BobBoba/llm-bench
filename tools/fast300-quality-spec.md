# Спека: качество быстрых LLM (300+ tok/s) для агентных сценариев

Дизайн-документ исследования, утверждён [[03.07.2026]]. Цель — измерить не «скорость» (уже есть), а **пригодность** быстрых моделей OpenRouter к повседневной агентной работе: надёжность tool-calling, работа с огромным контекстом, экономика.

## Мотивация

Существующие батареи (RUST/TS/знания) меряют корректность кода и эрудицию, но **не** меряют: надёжность многоходового tool-calling, деградацию на длинном контексте, реальную стоимость агентного цикла. Колонка «агентность» для fast100 = `N/A` (tool-loop не гонялся). Это исследование добавляет два новых измерения.

## Набор моделей (11)

**Тир 300+ tok/s (8), streaming-медиана по реальным вызовам батарей:**
`google/gemini-3.1-flash-lite`, `google/gemini-3.1-flash-lite-preview`, `google/gemini-2.5-flash-lite`, `google/gemini-2.5-flash-lite-preview-09-2025`, `amazon/nova-2-lite-v1`, `amazon/nova-micro-v1`, `inception/mercury-2` (диффузия), `x-ai/grok-4.20-multi-agent`.

**Якоря сравнения 200-300 tok/s (3):** `x-ai/grok-4.20`, `moonshotai/kimi-k2-thinking`, `google/gemini-3.5-flash`.

Четыре варианта gemini-flash-lite оставлены намеренно — показывают дельту качества 2.5→3.1 и preview→stable на одинаковых тестах.

## Харнесс A — надёжность tool-calling (`run-tooluse.mjs`)

Детерминированный mock «бизнес-API» из 4 инструментов, которые нужно связать в цепочку:
- `list_customers()` → список клиентов (id + имя);
- `get_orders(customer_id)` → заказы клиента (item + qty);
- `get_price(item)` → цена за единицу (fan-out на несколько товаров);
- `submit_total(customer_name, total)` → терминальный вызов с итогом.

Задача: «найди клиента Acme, посчитай сумму всех его заказов, отправь итог». Правильная сумма известна заранее → объективный скоринг. K=3 прогона на модель (замер флака).

**Метрики:** `success%` (отправлен верный итог), `valid_call%` (доля корректных tool-call: парсится JSON + известное имя + валидна схема), `malformed` (галлюцинации инструментов / битый JSON), `steps`, cost, latency, tokps.

**Гвард:** модели с `tools:false` в meta (`grok-4.20-multi-agent`) → tool-use `N/A` честно, без фейкового 0.

## Харнесс B — огромный контекст (`run-longctx.mjs`, обобщён на ZDR-OpenRouter)

Needle-in-haystack: уникальный код-игла `QX-73519-ZP` в детерминированном filler, скоринг по точному вхождению в ответ. Существующий харнесс обобщается с `lmstudio-client` на `CLIENT_MAP` (как остальные раннеры).

**Лестница длин — от окна КАЖДОЙ модели:** рунги `[8k, 25%·ctx, 50%·ctx, 75%·ctx]` (дедуплицируются, убираются ≤ предыдущего). Максимум = **75% окна модели** (требование заказчика).
**Глубины:** 10/50/90 на рунгах ≤256k; на рунгах >256k только 50 (контроль стоимости гигантского prefill).

**Метрики:** retrieval accuracy по сетке (длина × глубина), overall% и @макс-рунг%, prefill-латентность (реальная цена длинного контекста), promptTok из usage.
